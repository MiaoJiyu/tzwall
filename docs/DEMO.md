# 泰兴中学校园墙 — 运行示例

本机已部署完成（Ubuntu 24.04 + PostgreSQL 16 + Redis + Nginx + Go 后端），可直接访问。

## 一、访问地址

| 入口 | 地址 |
|---|---|
| 站点首页 | http://127.0.0.1/ 或 http://192.168.100.34/ |
| 后台管理 | http://127.0.0.1/admin/dashboard |
| 健康检查 | http://127.0.0.1/api/health |

## 二、演示账号

| 角色 | 账号 | 密码 | 说明 |
|---|---|---|---|
| 超级管理员 | `admin` | `Admin@123456` | 可访问权限矩阵、处罚管理、举报审核、全部后台 |
| 学生 | `student01` | `Student@123` | 普通用户，已发布 3 条投稿、评论与点赞 |

## 三、演示链路

### 1. 浏览与互动
1. 打开首页：查看最新/热门排序、标签筛选、搜索、右侧热榜。
2. 点击任意投稿进入详情：查看图文、点赞/点踩、复制分享链接。
3. 未登录时评论、点赞、举报入口会提示登录。

### 2. 注册与登录
1. 打开 `/register`：用户名 6–12 位、邮箱唯一、真实姓名与就读学校（仅后台可见）、勾选三份协议。
2. 未配置 SMTP 时无需邮箱激活，注册后可直接登录；登录支持“用户名或邮箱 + 密码”。

### 3. 投稿与审核
1. 用 `student01` 登录 → 顶部“发布” → 填写标题、正文、标签（可自定义待审标签）、上传图片（写入 COS 私有对象，经后端代理返回原图）。
2. 投稿提交后依次经过：违禁词预检 → 腾讯云文本审核 → AI 复审（启用时）；任一环节异常都会在页面上给出对应状态。
3. 用 `admin` 登录 → 后台“投稿审核” → 通过 / 需要修改 / 不通过，可填写仅投稿人可见的审核意见。
4. 通过后投稿出现在首页与“我的投稿”。

### 4. 举报与处理
1. `student02` 登录 → 打开投稿 #1 → “举报” → 填写理由提交。
2. 重复举报同一内容会提示“您已举报过该内容”；每用户每小时 5 次、每日 20 次。
3. `admin` → 后台“举报审核” → 选择“无明显违规”或“撤下内容”，**处理理由必填**（对举报人展示）；可同时处罚举报人或被举报人。
4. 举报人可在“我的权限变更记录 → 我的举报”查看处理结果与理由。

### 5. 处罚全流程
1. `admin` → 后台“处罚管理” → 新增处罚：警告 / 禁言 / 封禁用户名 / 强制修改用户名与密码；支持永久或自定义到期时间。
2. 警告：被处罚用户下次访问会看到 403 式弹窗（理由、时间、警告人），确认一次后不再出现。
3. 禁言：`student03` 登录后顶部常驻禁言横幅；投稿、评论、点赞、点踩、分享、举报均被禁用（后端统一返回 41005）。
4. 封禁 IP：后台“处罚管理 → IP 封禁”，支持 IPv4/IPv6/CIDR，命中后访问直接 403 并显示理由与到期时间。
5. 强制改密：管理员指定新用户名，系统生成临时密码（接口一次性返回给管理员），旧 Token 立即失效，下次登录强制改密。
6. 撤销：处罚记录保留并标记“已撤销”，其他叠加处罚继续生效；强制改密撤销后不恢复原用户名/密码。

### 6. 访问权限矩阵（仅超管）
1. `admin` → 后台“访问权限”。
2. 切换“普通用户默认权限集 / 普通管理员默认权限集 / 未登录访客权限集”，或填写用户 ID 做单用户覆盖。
3. 每个端点可配置是否允许与 rps/rpm/rphour/rpday 四档速率（0 表示不限）。
4. 保存后立即生效：未授权端点返回 41011（前端提示“请求端点失败，请联系系统管理员”），超限返回 429。
5. 页面权限由后端 `/api/meta/routes` 下发，前端守卫据此跳转 403。

### 7. COS 与内容审核联调
1. 登录后“发布”投稿并上传图片：图片写入 COS 私有对象，上传后立即调用数据万象图片审核（结果记录在 `moderation_tasks`）。
2. 提交投稿时同步调用文本审核：通过则自动 `approved`，可疑/违规/失败转 `pending` 人工。
3. 图片代理 `GET /api/images/{id}`：后端从 COS 取流后直接返回原图（**不再烧录水印**，全站水印由前端覆盖层承担），按图片 ID 短缓存；防盗链校验 Referer。
4. 审核结果通过数据万象回调（`/api/moderation/callback`，按 JobId 关联）与 60 秒轮询双通道落地。

### 8. 系统配置中心（仅超管）
1. `admin` → 后台“系统配置”，左侧切换分组：站点 / 注册登录 / 发帖评论 / 图片 / 审核与 AI / 举报 / 日志 / 运维 / 页脚备案。
2. 修改任意项后点击“保存”，立即生效；标记“需重启”的项会给出提示。
3. “审核与 AI”分组可启用 AI 审核并填入 OpenAI 兼容接口（密钥加密存储、掩码回显）。
4. 页面底部展示 `.env` 中的密钥配置状态（仅已配置/未配置，不显示内容）。

### 9. 投稿审核新流程
投稿发布后依次经过：

```
违禁词预检 → 腾讯云文本审核 →（通过）→ AI 复审 →（通过）→ 直接放行
                    ↓ 调用异常            ↓ 异常/超时/超限
                直接驳回(rejected)      转人工(pending)
                    ↓ 违规
                直接驳回(rejected)
```

- 云审核通过但 AI 未启用：转人工（不自动放行）。
- 驳回原因写入 `admin_note`，在“我的投稿”对作者可见。
- 审核过程可在“访问日志”“审计日志”与 `moderation_tasks` 表中追溯。

### 10. 词表与协议
1. “系统配置 → 词表管理”：违禁词直接拦截，常用词仅记录；支持换行/逗号批量导入。
2. “系统配置 → 协议版本”：编辑正文发布新版本（版本号 + 生效时间），右侧时间线可查看与回滚历史版本；发布后已登录用户下次访问需重新确认。

### 11. 日志与运维
1. “访问日志”：按时间/路径/方法/状态码/用户/IP 筛选，点击行查看请求头与请求体摘要（敏感字段已脱敏）。
2. “审计日志”：查看配置修改、处罚、审核、权限、协议与词表变更记录。
3. “运维面板”：磁盘/数据库/COS 用量四张指标卡、服务健康矩阵、备份文件列表；磁盘或 COS 超阈值时顶部出现告警条。

## 四、服务管理

```bash
# 重新构建并发布（后端 + 前端 + Nginx + 重启）
bash deploy/deploy.sh

# 仅启停后端
bash deploy/run.sh
bash deploy/stop.sh

# 重新写入演示数据
python3 deploy/seed-demo.py

# 日志
tail -f /var/log/tzwall.log
journalctl -u nginx -n 50
```

进程方式：本环境无 systemd，后端以 `setsid` 后台运行，PID 文件 `/var/run/tzwall.pid`；正式机可直接使用 `deploy/tzwall.service`。

## 五、当前能力状态

| 能力 | 状态 | 说明 |
|---|---|---|
| 数据存储 | 腾讯云 COS（已接入） | Bucket `tzwall-1321423822`，区域 `ap-nanjing`，对象私有读写；浏览器只经后端代理取流，代理时烧录水印；COS 未命中时回退本地磁盘（兼容存量数据） |
| 内容审核 | 数据万象（已接入） | 文本/图片同步审核 + 回调（`POST /api/moderation/callback`）+ 60 秒轮询双通道；可疑、违规或调用失败一律转人工，绝不自动放行 |
| 邮件 | 已配置 | SMTP `smtp.163.com:465`（`.env` 或后台“系统配置”录入，后台优先）；发信失败不影响主流程，找回密码在邮件不可用时自动隐藏 |
| Redis | 已启用 | `127.0.0.1:6379`，用于限流、登录锁定、处罚快照缓存 |
| 水印 | 已启用 | 全站平铺水印（用户名/游客 + IP + 时间）；**图片文件不再烧录水印** |
| 访问日志 | 已记录 | 接近全量（方法/路径/查询/关键 Header/IP/UA/用户/状态/耗时/请求体摘要），敏感字段脱敏，保留 90 天；查看页在阶段三 |
| 审核 BizType | 未配置 | 使用 Bucket 默认审核策略；如需自定义策略，配置 `COS_AUDIT_BIZ_TYPE` 并在 COS 控制台创建对应策略 |
| 回调校验 | 未配置 | 配置 `COS_CALLBACK_TOKEN` 后，回调需带 `X-Cos-Callback-Token` 头 |

**COS 控制台回调配置**（可选）：内容审核 → 审核策略 → 回调 URL 填 `https://<域名>/api/moderation/callback`。

## 六、安全提示

- 腾讯云 SecretId/SecretKey 仅写入 `backend/.env`（权限 600），未入库、未下发前端、未写入日志。
- 该密钥已在对话中明文出现，**建议尽快在腾讯云控制台轮换**，并同步更新 `backend/.env` 后重启服务。
- 生产环境请替换 `JWT_SECRET`、数据库密码与管理员初始密码。
