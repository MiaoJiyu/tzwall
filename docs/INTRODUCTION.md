# 泰兴中学校园墙 · 产品介绍

> 一个安全、好用、可运营的校园社区平台。

---

## 一、一句话定位

**泰兴中学校园墙**是专为中学师生打造的校园社区：让校园里的想法被看见、被讨论、被沉淀，同时把内容安全与治理交给系统，而不是靠人盯。

---

## 二、网站定位与核心价值

校园墙的价值不在"能发帖"，而在**发得出去、看得放心、管得起来**。本平台围绕这三点构建：

- **发得出去**：投稿、评论、点赞、投票、点歌、私聊、工单，覆盖校园日常表达与协作。
- **看得放心**：内容先审后发，机审 + AI 复审 + 人工兜底，违禁词实时拦截。
- **管得起来**：举报、处罚、权限矩阵、配置中心、日志审计与运维面板，治理闭环开箱即用。

---

## 三、主要功能

| 板块 | 能力 |
| --- | --- |
| 内容社区 | 投稿发布/编辑/撤回、多级评论、点赞点踩、标签分类、图文与视频 |
| 互动玩法 | 投票（可关联投稿）、点歌（周配额）、私信会话 |
| 校园服务 | 公告与必读确认、工单（故障/反馈/申诉/账号）、用户公开主页 |
| 内容安全 | 腾讯云内容安全 + AI 复审 + 人工兜底、违禁词拦截、盲水印溯源 |
| 治理后台 | 举报处理、处罚（警告/禁言/封号/封 IP）、权限矩阵、配置中心、访问/审计日志、运维面板 |
| 多端覆盖 | 桌面端与移动端自适应 Web，配套微信小程序 |

---

## 四、目标用户

- **学生**：浏览校园动态、投稿表达、参与投票与点歌、私信交流。
- **教师与社团**：发布公告、组织活动、引导讨论、收集反馈。
- **学校管理员/运营**：审核内容、处理举报与工单、管理用户与权限。
- **技术维护人员**：通过配置中心、日志与运维面板低成本维护。

---

## 五、相较于同类产品的独特价值

### 1. 安全：把"先审后发"做成默认能力

多数校园墙是"发出去再删"，风险滞后。本平台默认**先审后发**：机审拦截违规，AI 复核语境，异常一律转人工；配合违禁词、举报闭环与处罚体系，把风险挡在公开展示之前。

### 2. 易用：师生零学习成本，管理员一屏可管

- 前端为现代化单页应用，桌面/手机自适应，交互顺滑。
- 学生端只有"看、发、评、投"几条主路径，无需培训。
- 管理后台聚合审核、举报、工单、用户、配置、日志，一屏完成日常治理。

### 3. 性能：为校园网络与流量成本做了优化

- 图片/视频经统一代理与对象存储分发，支持 CDN 与源站缓存，减少回源流量。
- 高频轻接口启用 ETag 协商缓存，重复访问多为 304。
- 可选 Redis 缓存热点数据，列表与详情响应更快。

### 4. 安全（工程侧）：权限与数据双重护栏

- **端点级权限矩阵**：用户覆盖 > 角色默认 > 公开白名单 > 默认拒绝，并可对每个端点设置四档限流。
- **敏感配置 AES 加密**存储、不可回显；JWT 鉴权、登录失败锁定、Token 版本失效。
- 访问日志与审计日志留痕，敏感字段脱敏，IP 仅超管可见。

### 5. 可扩展：模块化 + 可降级，随规模平滑演进

- 业务按模块拆分，新增能力不动存量。
- 对象存储、内容审核、邮件、AI、缓存均为可替换接口，未配置自动降级，不阻塞上线。
- 配置中心热更新，多数运营策略改完即生效，无需停机发版。

### 6. 对比一览

| 维度 | 常见校园墙 | 泰兴中学校园墙 |
| --- | --- | --- |
| 内容安全 | 事后删除 | 先审后发 + AI 复审 + 人工兜底 |
| 权限管理 | 粗粒度账号 | 端点级权限矩阵 + 四档限流 |
| 运营配置 | 改代码/重启 | 配置中心热更新 |
| 外部依赖 | 强绑定 | 接口化、可降级 |
| 多端 | 单一网页 | Web 自适应 + 微信小程序 |
| 治理闭环 | 分散 | 举报/处罚/工单/公告一体 |

## 六、典型使用场景

- **校园热点讨论**：一条投稿引发讨论，评论、点赞、投票联动，形成话题场。
- **活动组织与征集**：公告触达 + 必读确认 + 投票征集，快速收集意见。
- **意见反馈与申诉**：工单承接故障、建议与处罚申诉，处理过程可追踪。
- **内容治理**：举报进入后台，管理员核实后处罚或恢复，全程留痕。
- **校园点歌台**：社团或班级活动用点歌互动，配额防止刷屏。

---

## 七、适用建议

- **适合**：希望快速搭建校园社区、又需要内容安全与治理能力的中学；注重多端体验与低维护成本的团队。
- **上线建议**：先启用"先审后发 + 违禁词 + 举报"三件套，再按需开启 AI 复审与点歌/投票模块。
- **运营建议**：用公告与投票做冷启动，用工单沉淀反馈，用权限矩阵把审核职责下放到教师/社团。
- **部署建议**：单机即可起步；流量增长后接入对象存储 CDN 与 Redis，平滑扩容。

## 八、结语

**让表达更自由，让治理更省心。**  
泰兴中学校园墙用"安全默认、好用为先、可运营、可扩展"的设计，把校园社区从"能用"做到"敢用、好用、长期可用"。
